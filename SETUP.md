# Как развернуть сайт и подписку Loya — пошагово

Всё бесплатно (в рамках бесплатных тарифов Vercel и Supabase — карту нигде,
кроме Stripe, вводить не нужно). Платите только реальную комиссию Stripe с
платежей клиентов (обычно ~2.9% + фиксированная часть — точные цифры на
stripe.com/pricing для вашей страны).

Когда всё будет готово (созданы аккаунты) — пришлите мне ключи, и я доделаю
последний шаг: впишу адрес сервера в приложение.

---

## Шаг 1 — Stripe (приём оплаты)

1. Зарегистрируйтесь на **stripe.com** → создайте бизнес-аккаунт (понадобятся
   реальные данные вашего бизнеса — Stripe так проверяет, кому платить).
2. В панели Stripe: **Products** → **Add product** → назовите, например,
   «Loya — подписка», задайте цену и период **Recurring → Monthly**.
   Сохраните — откроется страница товара, там будет **Price ID** (начинается
   с `price_...`) — он понадобится ниже.
3. **Developers → API keys** — скопируйте **Secret key** (начинается с
   `sk_live_...` или `sk_test_...` для тестового режима — тестовый советую
   использовать первое время).
4. **Developers → Webhooks → Add endpoint** — сюда позже (после шага 3, когда
   будет адрес сайта) впишете `https://ВАШ-САЙТ.vercel.app/api/webhook` и
   выберете события: `checkout.session.completed`, `invoice.paid`,
   `invoice.payment_failed`, `customer.subscription.deleted`. После создания
   Stripe покажет **Signing secret** (начинается с `whsec_...`) — тоже
   понадобится.

## Шаг 2 — Supabase (база данных)

1. Зарегистрируйтесь на **supabase.com** → **New project** (бесплатно, карта
   не нужна).
2. **SQL Editor** → **New query** → вставьте содержимое файла `schema.sql`
   из этого комплекта → **Run**.
3. **Project Settings → API** — скопируйте:
   - **Project URL** (например `https://xxxxx.supabase.co`)
   - **service_role key** (НЕ anon/public — именно service_role, длинная
     строка). Это секретный ключ с полным доступом — никогда не публикуйте
     его и не вставляйте в код сайта напрямую, только в переменные окружения
     (см. шаг 3).

## Шаг 3 — Vercel (сам сайт + сервер)

1. Зарегистрируйтесь на **vercel.com** (можно через GitHub-аккаунт — тогда
   деплой при каждом изменении будет происходить автоматически).
2. Загрузите папку `loya-website` (эту) в свой репозиторий на GitHub, затем
   в Vercel: **Add New → Project** → выберите этот репозиторий → Deploy.
   (Если с GitHub возиться не хочется — у Vercel есть и просто перетаскивание
   папки через `vercel` в командной строке, но с GitHub удобнее для будущих
   правок.)
3. **Project Settings → Environment Variables** — добавьте:
   - `STRIPE_SECRET_KEY` — из шага 1.3
   - `STRIPE_PRICE_ID` — из шага 1.2
   - `STRIPE_WEBHOOK_SECRET` — из шага 1.4
   - `SUPABASE_URL` — из шага 2.3
   - `SUPABASE_SERVICE_KEY` — из шага 2.3 (service_role)
   - `PUBLIC_URL` — адрес самого сайта после деплоя, например
     `https://loya-website.vercel.app` (без слэша на конце)
4. После сохранения переменных — **Deployments → (три точки) → Redeploy**,
   чтобы они применились.
5. Вернитесь в Stripe (шаг 1.4) и впишите настоящий адрес вебхука:
   `https://ВАШ-АДРЕС.vercel.app/api/webhook`.

## Шаг 4 — проверка

1. Откройте `https://ВАШ-АДРЕС.vercel.app/pricing.html`, введите тестовый
   email, нажмите «Оформить подписку».
2. Если вы в тестовом режиме Stripe (ключи `sk_test_...`) — на странице
   оплаты используйте тестовую карту `4242 4242 4242 4242`, любой будущий
   срок действия, любой CVC.
3. После оплаты должно перенаправить на `success.html` с показанным
   лицензионным ключом.
4. Впишите этот ключ в приложении: **Настройки → 🔑 Подписка**.

## Шаг 5 — переключение на боевой режим

Когда всё проверено на тестовых ключах — в Stripe переключитесь в **Live
mode** (переключатель вверху панели), пройдите проверку бизнеса, если ещё не
проходили, возьмите **боевые** ключи (`sk_live_...`) и обновите переменную
`STRIPE_SECRET_KEY` в Vercel, а также пересоздайте товар и вебхук уже в
боевом режиме (они у Stripe отдельные для теста и боевого режима).

---

## Что дальше нужно от меня

Как только сайт развёрнут и работает — пришлите мне адрес (например
`https://loya-website.vercel.app`), и я одной строкой впишу его в
приложение (`SUBSCRIPTION_API_URL` в `main.js`) — это последний шаг, после
которого проверка подписки заработает по-настоящему, а не только в
настройках.

## Google Wallet (карты клиентов в телефоне)

Карты выпускает сайт от имени вашего аккаунта эмитента — клиентам программы ничего
настраивать не нужно. В Vercel → Project → Settings → Environment Variables добавьте:

- `GOOGLE_WALLET_ISSUER_ID` — идентификатор эмитента из Google Pay & Wallet Console
- `GOOGLE_WALLET_SERVICE_ACCOUNT` — полное содержимое JSON-ключа сервисного аккаунта
  (открыть файл блокнотом, скопировать всё целиком от `{` до `}`)

После добавления — Deployments → последний деплой → «Redeploy».
Функции: `api/wallet-link.js` (ссылка «Добавить в Google Wallet»), `api/wallet-update.js`
(обновление штампов после скана), общий код — `api/_wallet.js`.

## Индивидуальные карты в Google Wallet (v2)

Раньше все карты выглядели одинаково — только текстом. Теперь у каждой карты есть
картинка-баннер (heroImage), которую сервер рисует сам:
- своя для каждого бизнеса — название, фирменный цвет, значок вида бизнеса (кофейня,
  барбершоп, салон и т.д.);
- живая для каждого клиента — на штамп-карте видно сами штампы кружками, на
  накопительной — шкалу прогресса, на скидочной — крупный процент. Обновляется сама
  после каждого скана.

Файлы: `api/wallet-hero.js` (отдаёт PNG по запросу от Google), `api/_walletHero.js`
(рисует SVG → PNG через `@resvg/resvg-js`, шрифт Carlito лежит в `api/fonts/`,
лицензия OFL — файл `api/fonts/Carlito-LICENSE.txt` идёт вместе с шрифтом).

Ничего дополнительно настраивать не нужно — работает сразу при тех же переменных
`GOOGLE_WALLET_ISSUER_ID` и `GOOGLE_WALLET_SERVICE_ACCOUNT`, что и раньше.

## Рабочая почта Loya (письма клиентам без настройки)

Программа отправляет письма через `POST /api/send-mail` — пароль почты лежит только на сервере.
В Vercel → Settings → Environment Variables добавьте:

- `MAIL_USER` — адрес отправителя (например `loya.loyalty.send@gmail.com`)
- `MAIL_PASS` — пароль приложения этого ящика
- необязательно: `MAIL_HOST` (по умолчанию smtp.gmail.com), `MAIL_PORT` (465),
  `MAIL_DAILY_PER_LICENSE` (300 писем в сутки на подписку), `MAIL_DAILY_GLOBAL` (450 всего в сутки)

Затем выполните в Supabase → SQL Editor кусок про `mail_log` из `schema.sql` и сделайте Redeploy.

⚠️ Gmail пропускает около 500 писем в сутки на ВЕСЬ ящик. Для нескольких десятков бизнесов
перейдите на почтовый сервис (Brevo, Resend, Amazon SES, Mailgun) с вашим доменом
loya-loyalty.com: достаточно поменять MAIL_HOST / MAIL_PORT / MAIL_USER / MAIL_PASS, программу
обновлять не нужно.

## Домен loya-loyalty.com

Vercel → проект → Settings → Domains → Add `loya-loyalty.com` и `www.loya-loyalty.com`,
дальше Vercel покажет, какие DNS-записи добавить у регистратора домена (обычно A-запись
76.76.21.21 и CNAME для www). После этого поменяйте `PUBLIC_URL` в переменных окружения на
`https://loya-loyalty.com`.


## Регистрация клиентов по ссылке (Instagram и т.п.)

Как работает: владелец включает «Настройки → Регистрация по ссылке» — программа публикует его
профиль (название, цвет, значок вида бизнеса, бонус) на этом сайте и получает ссылку вида
`/r/<название>-<код>`. Клиент открывает её с телефона, регистрируется и получает бонусный QR-купон
со сроком (и копию на email). Программа на кассе раз в минуту забирает новые заявки через
`/api/online-pull`, заводит клиента и бонусную карту. При визите бонус гасится и выдаётся
постоянная карта; не успел до конца срока — бонус сгорает, но постоянная карта всё равно выдаётся.

Что сделать один раз:
1. Supabase → SQL Editor → выполнить блок про `business_profiles` и `online_registrations`
   из конца `schema.sql`.
2. Загрузить файлы сайта на GitHub (новые: `api/_online.js`, `api/profile-publish.js`,
   `api/online-register.js`, `api/online-pull.js`, `api/reg-page.js`, `vercel.json`) и сделать
   Redeploy (подтянется зависимость `qrcode`).
3. Ссылки строятся от `PUBLIC_URL` — после подключения домена поменяйте её на
   `https://loya-loyalty.com`.

Файл `vercel.json` содержит переписывание `/r/:slug` → `/api/reg-page`. Если у вас уже есть
свой `vercel.json`, добавьте в него только блок `rewrites`.

Защита: поле-ловушка для ботов, не больше 12 регистраций в час с одного адреса, не больше 300 в
сутки на бизнес (`ONLINE_REG_DAILY_PER_BUSINESS`), один купон на номер телефона.
Письмо с купоном уходит через рабочую почту Loya (`MAIL_USER` / `MAIL_PASS`).


## Доступ из дома (статистика и правки клиентов с телефона)

Владелец включает «Настройки → Доступ из дома», задаёт пароль (от 8 символов) и получает личную
ссылку вида `/owner/<48 символов>`. Программа раз в 2 минуты отправляет на сайт копию показателей и
списка клиентов (`/api/owner-sync`) и забирает правки (добавить/изменить клиента), которые владелец
сделал на странице. Страница: вход по паролю (8 неверных попыток — блокировка на 15 минут),
сессия 12 часов. Выключил — копия и очередь правок удаляются с сервера.

Что сделать один раз:
1. Supabase → SQL Editor → блок про `owner_access` и `owner_commands` из `schema.sql`.
2. Загрузить файлы сайта на GitHub (новые: `api/_owner.js`, `api/owner-sync.js`, `api/owner-login.js`,
   `api/owner-data.js`, `api/owner-command.js`, `api/owner-page.js`; обновлён `vercel.json`) и Redeploy.
3. По желанию задайте `OWNER_SECRET` (любая длинная случайная строка) в переменных окружения Vercel —
   ею подписываются сессии. Если не задана, ключ строится из `SUPABASE_SERVICE_KEY`.

Важно: данные берутся с компьютера на кассе — он должен быть включён, программа запущена и с
интернетом. Если связи нет дольше 20 минут, страница предупреждает, что данные могут быть устаревшими.
Политика конфиденциальности (`privacy.html`) уже описывает эти функции.


## Переход на домен loya-loyalty.com — что проверить

1. Vercel → Settings → Environment Variables: `PUBLIC_URL` = `https://loya-loyalty.com` (без «/» в конце).
   От неё зависят возврат после оплаты Stripe, ссылки регистрации и доступа из дома, картинки карт Google Wallet.
2. Stripe → Developers → Webhooks: адрес должен быть `https://loya-loyalty.com/api/webhook`
   (если после переезда старый адрес перестал отвечать).
3. Если сайт переехал в НОВЫЙ проект Vercel — в нём должны быть все переменные окружения старого:
   `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`,
   `GOOGLE_WALLET_ISSUER_ID`, `GOOGLE_WALLET_SERVICE_ACCOUNT`, `MAIL_USER`, `MAIL_PASS`. После добавления — Redeploy.
4. Быстрая проверка: откройте `https://loya-loyalty.com/api/health` — вернётся строка с `"ok":true`
   и признаками `wallet`, `mail`, `db` (true/false). Тот же отчёт — кнопка «Проверить связь с сервером»
   в программе (Настройки → Подписка).
Программа 1.95.1 ходит на loya-loyalty.com, а если он не отвечает — на запасной loya-website-one.vercel.app.


## Почему сайт «не обновлялся» и что изменено (лимит Vercel)

На бесплатном тарифе Vercel Hobby в одном деплое может быть не больше 12 серверных функций.
Раньше каждый адрес был отдельным файлом (18 штук), поэтому свежие деплои отклонялись, а на сайте
оставалась старая версия. Теперь функций 8:
`verify-license`, `webhook`, `create-checkout-session`, `get-license-by-session`
и четыре общих — `wallet`, `online`, `owner`, `core`. Прежние адреса (`/api/wallet-link`,
`/api/owner-sync`, `/r/<slug>`, `/owner/<token>` и т.д.) работают как раньше — их направляет `vercel.json`.
Файлы с подчёркиванием в начале (`_wallet.js`, `_x_*.js` …) функциями не считаются — это общий код.

Как убедиться, что деплой прошёл: Vercel → Deployments → самый верхний должен быть «Ready» (зелёный).
Если красный «Error» — откройте его и прочитайте текст ошибки. Затем:
`https://loya-loyalty.com/api/health` должен вернуть строку с `"ok":true`.

Заметка: тариф Hobby у Vercel — для личных некоммерческих проектов. Для платного сервиса с подписками
честнее перейти на Pro (около $20 в месяц): там нет лимита на число функций и дольше работают функции.


## Админка подписок — loya-loyalty.com/admin

Только для владельца сервиса. Показывает всех клиентов (ключи), сколько платят, сколько на бесплатном
доступе, кто заблокирован и кто выходил на связь за последние 7 дней (с какой версией программы).
Можно: выдать бесплатный доступ (новый ключ, по желанию — до даты), сделать существующий ключ
бесплатным или вернуть платным, заблокировать / разблокировать, оставить заметку.

Что сделать один раз:
1. Supabase → SQL Editor → выполнить весь `schema.sql` (в конце — новые колонки для `licenses`).
2. Vercel → Environment Variables → `ADMIN_PASSWORD` = длинный пароль (не короче 12 символов).
   Пока переменной нет, админка выключена. Смена пароля сразу выкидывает все открытые сессии.
3. Redeploy.

Правила доступа: блокировка действует всегда, даже если Stripe продлил подписку; бесплатный ключ
работает независимо от Stripe (и до даты, если она указана); обычный ключ — пока подписка активна.


## Касса → Loya (чеки, бонусы, склад)

Фискальный чек по-прежнему печатает сертифицированная касса бизнеса (eKasa и т.п.) — Loya кассой
не является. Касса присылает копию чека, Loya начисляет бонусы и списывает товары со склада.

Два способа:
1. **По сети заведения** — касса шлёт `POST http://<компьютер>:<порт>/api/pos/receipt` с заголовком
   `Authorization: Bearer <токен>`. Адрес и токен — в программе: Настройки → «Подключение кассы».
2. **Через интернет** (облачные кассы с веб-хуком) — `POST https://loya-loyalty.com/api/pos/<ключ>`.
   Чеки ждут в очереди (таблица `pos_events`), программа забирает их раз в минуту.

Формат чека (JSON): `id`, `total`, `currency`, `created_at`, `card` (код карты) или `phone`,
`items: [{ name, sku, barcode, qty, price }]`. Понимаются и другие названия полей
(`receipt_id`, `amount`, `lines`, `plu`, `quantity`, `unit_price`…). Повторно присланный чек не
начисляет бонусы второй раз.

Что сделать один раз: выполнить весь `schema.sql` в Supabase (таблицы `pos_keys`, `pos_events`).
Новых функций Vercel не добавлено — всего 9 из 12.


## Боевой запуск (оплата и Google Wallet)

Пошаговая инструкция — в файле `GO_LIVE.md`. Состояние запуска всегда видно в админке
(`loya-loyalty.com/admin` → «🚀 Готовность к запуску»).

Новые переменные Vercel для боевого режима: `STRIPE_PORTAL_URL` (ссылка на кабинет клиента в Stripe),
`MAIL_FROM` и `SUPPORT_EMAIL` (адрес отправителя на своём домене и адрес для ответов),
необязательно `STRIPE_COLLECT_TAX_ID=1`. После обновления выполните весь `schema.sql` в Supabase
(колонка `livemode` и защита от дубликатов ключа).
